# Reference integration

The approved 6 November Corporate UX review supersedes the original horizontal header and role flows described below. The app now uses navy corporate surfaces, three sidebar destinations per role, unified OTP, paired programs and scoring versions. See [Corporate UX acceptance](CORPORATE_UX_ACCEPTANCE.md).

Reviewed the reference package's `README_START_HERE.md` first, then the four distinct HTML implementations and associated server logic, tests and requirements. The three loose HTML files supplied from Downloads were hash-compared with the package: Prism matched `01_Prism_Studio/index.html`; both AI Time-Back copies matched `02_AI_Time_Back_360/index.html`.

All four screenshots were visually inspected: Landing, Host, Test, and Mobile Registration. This implementation preserves their #f5f7ff canvas, #1d2852 ink, #5359df primary, lavender/pink/mint radial gradients, rounded T mark, 72px horizontal header, 19–23px card radii, light surfaces, subtle borders and narrow-screen registration treatment. Host cards retain the colored baseline accents. Assessment cards retain the multicolor top rule and soft task navigation. The responsive application includes actual server-backed interactions rather than embedded screenshots.

AI Time-Back 360's most useful ideas are paired Base Camp/Summit results, completion visibility, elapsed time, accuracy, quality, cohort summaries and a transparent capacity-value scenario. Its browser-local user store and optimistic financial claims are not carried over. The application does not select a best later attempt or combine the fastest task time with a different attempt's score. It compares the single submitted linked Pre/Post pair and retains negative changes.

The FastAPI pilot informed opaque identity/session handling, server timing, restricted host exports, manual grading and export fields. The temporary HTTP prototype informed explicit timeout finalization and retention of the last saved work. Their host secrets in browser storage, RAM dictionaries, temporary evidence stores and weak identity verification were replaced.

The original inbox brief has been preserved: 100 emails, 67 question messages, Guru receivables, unreplied messages, repeated themes and an FAQ workbook. All five categories remain independent. The user's request takes precedence over legacy prototype behavior: participants choose any three of five; the default duration is 60 minutes; identity is verified; Pre/Post categories match; storage is SharePoint; automatic MCQ marking and practical evaluation are separate.

No reference scripts were run and no prototype storage was imported. No Microsoft tenant/library credentials were present or inferred from the files.
